# 需求分析

1. 从 PRD、原型说明和已确认决策界定目标、参与者、触发条件、依赖及排除项。
2. 按业务操作与可观察结果提取场景 `SC`，保留来源。页面、接口和组件可作为定位线索。
3. 提取规则 `BR`，记录适用条件、权限、字段约束、允许或禁止的行为及失败结果。有状态的场景补充起始状态、动作、条件和目标状态。
4. 检查适用的空值、边界值、重复操作、状态冲突、并发、依赖失败、撤回和重试。按业务影响区分明确规则与未决行为。
5. 为需要决策的问题分配 `Q`，列出影响的 `SC`、`BR`、`AC`、阻塞程度及有依据的候选方案。明确哪些结论可先交付。

在 [规格模板](../assets/acceptance-spec.template.md) 中使用范围、场景、规则与状态、待确认项四部分。
