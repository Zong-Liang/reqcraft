# 验收审计

先列明实际可用的 PRD、现有规格、仓库位置和运行报告。默认在对话交付，用户明确要求写入时才在已有规格追加或更新审计记录。

1. **覆盖与一致性**。逐项核对 PRD → `SC` → `BR` → `AC`，识别遗漏的场景、失败路径和状态边界。核对规则冲突、前后端责任冲突，以及待定规则被误标为确认的情况。
2. **可验证性**。核对前提、动作和结果是否具体，能否判定通过或失败。静态格式检查可参考 [校验脚本](scripts-check.md)。
3. **实现线索**。有源码时定位对应逻辑与缺失位置，记录路径及符号。源码和测试文件可说明实现或验证意图，运行结果需独立证据。
4. **已有验证证据**。匹配 AC、测试身份和报告结果。记录报告位置、覆盖范围，以及已知的环境、版本和时间。旧报告或环境不明时限定结论适用范围。缺少可核实的运行结果时标为「证据不足」。

按对象使用「已确认」「待确认」「未覆盖」「存在实现线索」「已有通过证据」「已有失败证据」「证据不足」或「不适用」。问题注明位置、关联 AC、影响和交接对象。没有 AC 的覆盖缺口引用对应场景、规则或 PRD 位置。

结论分别记录规格质量、技术映射、实现线索和验证证据。通过或失败只适用于报告对应的 AC 和运行条件。审计期间禁止执行测试。
